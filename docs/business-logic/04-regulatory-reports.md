# 04. Regulatory Reports

## วัตถุประสงค์ทางธุรกิจ

รองรับการออกรายงานตามกฎหมายร้านยาไทย โดยใช้ข้อมูลที่ตรวจสอบย้อนหลังได้ และลดความเสี่ยงจากการบันทึกรายงานไม่ครบหรือคลาดเคลื่อน

## สถาปัตยกรรมธุรกิจปัจจุบัน

- Backend รับผิดชอบการให้ข้อมูลดิบที่ผ่าน authorization แล้ว
- Frontend รับผิดชอบการสร้างเอกสาร HTML, preview, print และ save as PDF
- CSV หรือไฟล์เชิง machine-readable บางประเภทสามารถยังสร้างจาก Backend ได้

## Business Rules สำหรับ KHY Reports

### ข.ย. 9

- แหล่งข้อมูลหลักคือเอกสารรับสินค้า
- รายการต้องแสดงเฉพาะสินค้าที่มีการผูกกับข้อมูลยาอย่างถูกต้อง
- รายงานต้องอ้างอิงช่วงวันที่ของการรับเข้าและสาขาที่ผู้ใช้มีสิทธิ์

### ข.ย. 10–13

- แหล่งข้อมูลหลักคือ orders (order_items joined with products)
- คัดกรองโดยใช้ `product.DrugRegistrations` array (ค่า: KHY10, KHY11, KHY12, KHY13)
- ไม่ได้ใช้ `product.DrugInfo.DrugType` ในการคัดกรอง
- ต้องแสดงข้อมูลเภสัชกร (`pharmacistName`) และเลขใบอนุญาต (`licenseNo`) ซึ่งดึงจาก order entity
- รายงานต้องดึงเฉพาะรายการที่ order มีสถานะ ACTIVE ในช่วงวันที่และสาขาที่กำหนด

## Business Rules สำหรับเอกสารเชิงพาณิชย์

### ใบเสร็จ / ใบกำกับภาษี

- ต้องอ้างอิง order ที่ยืนยันแล้ว
- รายการสินค้า ยอดรวม ส่วนลด และการชำระเงินต้องตรงกับข้อมูล order จริง
- ใบกำกับภาษีต้องแสดงข้อมูลภาษีตาม setting หากมี

### รายงานขาย

- ใช้ข้อมูล order ในช่วงวันที่ที่กำหนด
- การคำนวณยอดรวมต้องตัดสถานะที่ไม่ควรถูกรวม เช่น cancelled / voided

### ประวัติลูกค้า / ประวัติสินค้า / สรุปรับสินค้า

- ต้องแสดงข้อมูลย้อนหลังตามข้อมูลจริงในระบบ
- ใช้เพื่อการตรวจสอบและวิเคราะห์ ไม่ใช่เพียงการพิมพ์เอกสาร

## Validation Rules

- ผู้ใช้ต้องมีสิทธิ์เข้าถึงรายงาน
- date range ต้องมีค่าเริ่มและสิ้นสุดที่ถูกต้อง
- buyer / pharmacist / licenseNo / prescriber data ต้องครบเมื่อสินค้าอยู่ในกลุ่มควบคุม
- เลขบัตรประชาชนผู้ซื้อต้องเป็นรูปแบบ X-XXXX-XXXXX-XX-X
- report data ต้องถูกกรองตาม branch context
- หากข้อมูลไม่พอสร้างเอกสาร ต้องแสดงสถานะไม่มีข้อมูล ไม่ใช่สร้างเอกสารผิดรูปแบบ

## Edge Cases

- รายการถูกแก้ไขย้อนหลัง ต้องสะท้อนผลในรายงานรอบถัดไป
- หากข้อมูลอ้างอิงบางส่วนหาย เช่น product ถูก archive ต้องยังรักษาความสามารถในการแสดงรายงานย้อนหลังให้ได้มากที่สุด
- รายงาน KHY ที่ไม่มีรายการในช่วงนั้นต้องยังออกรายงานเปล่าได้

## Expected Outcomes

- รายงานตรวจสอบย้อนหลังได้
- ข้อมูลตรงกับเอกสารต้นทางในระบบ
- ลดภาระ backend ด้าน PDF rendering
- เพิ่มความยืดหยุ่นในการออกแบบเอกสารที่ frontend
