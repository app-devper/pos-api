# 12. Category Lifecycle

## วัตถุประสงค์

กำหนดสถานะของหมวดหมู่สินค้าเพื่อให้การจัดกลุ่มสินค้า การค้นหา และการวิเคราะห์เชิงธุรกิจมีความสม่ำเสมอ

## สถานะหลัก

- `DRAFT` — หมวดหมู่กำลังถูกสร้างหรือแก้ไข
- `ACTIVE` — พร้อมใช้งานและสามารถผูกกับสินค้าได้
- `INACTIVE` — ไม่ควรถูกใช้กับสินค้าใหม่ แต่ยังคงใช้เป็น reference ย้อนหลังได้
- `ARCHIVED` — เก็บไว้เพื่อประวัติและ compatibility กับข้อมูลเดิม

## Transition หลัก

### 1. `DRAFT -> ACTIVE`

#### Trigger

- ผู้ใช้บันทึกหมวดหมู่และเปิดใช้งาน

#### Preconditions

- ชื่อหมวดหมู่ไม่ซ้ำในขอบเขตที่ระบบกำหนด
- โครงสร้างข้อมูลพร้อมใช้งานกับสินค้า

#### Backend Effects

- category พร้อมถูกเลือกใน product create/edit flow

#### Frontend Behavior

- category ปรากฏใน dropdown, filter และ list ปกติ

### 2. `ACTIVE -> INACTIVE`

#### Trigger

- ปิดใช้งานหมวดหมู่

#### Effects

- ไม่ควรถูกเลือกกับสินค้าใหม่ใน flow ปกติ
- สินค้าเดิมที่ผูก category นี้ยังต้องอ่านย้อนหลังได้

#### Frontend Behavior

- แสดงสถานะ inactive
- ซ่อนจาก selector ปกติหรือแสดงแบบ disabled

### 3. `INACTIVE -> ACTIVE`

#### Trigger

- เปิดใช้งานอีกครั้ง

### 4. `ACTIVE/INACTIVE -> ARCHIVED`

#### Trigger

- เก็บไว้เพื่ออ้างอิงย้อนหลังโดยไม่ใช้ใน flow ปัจจุบัน

## ข้อควรระวัง

- ไม่ควรลบ category ที่ยังถูกอ้างอิงโดยสินค้าเดิม
- การเปลี่ยนชื่อหรือปิดใช้งานต้องไม่ทำให้รายงานและการวิเคราะห์ย้อนหลังเสียความหมาย
