# 05. Product Lifecycle

## วัตถุประสงค์

อธิบายวงจรชีวิตของสินค้าในระบบตั้งแต่สร้างข้อมูลครั้งแรกจนถึงการปิดใช้งาน เพื่อให้การขาย การรับเข้า รายงาน และการตรวจสอบย้อนหลังใช้ข้อมูลสินค้าอย่างสอดคล้องกัน

## สถานะหลัก

- `DRAFT` — ข้อมูลกำลังถูกสร้างหรือแก้ไข ยังไม่พร้อมใช้งานเชิงธุรกิจ
- `ACTIVE` — สินค้าพร้อมใช้งานใน workflow หลัก เช่น รับเข้า ขาย และรายงาน
- `INACTIVE` — สินค้าถูกปิดใช้งาน ไม่ควรถูกเลือกใช้ในรายการใหม่
- `ARCHIVED` หรือ `DELETED` เชิงตรรกะ — ไม่ใช้งานแล้ว แต่ยังต้องคงข้อมูลเพื่ออ้างอิงย้อนหลัง

## Transition หลัก

### 1. `DRAFT -> ACTIVE`

#### Trigger

- ผู้ใช้บันทึกข้อมูลสินค้าครบและเปิดใช้งาน

#### Preconditions

- มีข้อมูลบังคับ เช่น ชื่อสินค้า หน่วยหลัก ราคา หรือข้อมูลที่ระบบกำหนด
- ถ้ามีหลายหน่วย ต้องมี unit mapping ที่ใช้งานได้
- ถ้ามีบาร์โค้ด ต้องไม่ชนกับข้อมูลเดิมที่มีอยู่

#### Backend Effects

- สร้าง product record ให้พร้อมใช้งาน
- ทำให้สินค้าแสดงใน search, receives, POS, reports และ flow อื่นที่เกี่ยวข้อง

#### Frontend Behavior

- แสดงสินค้านี้ใน product list และ selector ต่าง ๆ
- พร้อมใช้งานสำหรับ print price list / price tags

### 2. `ACTIVE -> INACTIVE`

#### Trigger

- ผู้ใช้ปิดใช้งานสินค้า

#### Effects

- สินค้าไม่ควรถูกใช้ในการสร้างรายการใหม่ เช่น order หรือ receive ตามนโยบายที่กำหนด
- ข้อมูลประวัติเดิมยังต้องอ้างอิงสินค้าได้
- สินค้าที่เคยอยู่ในรายงานย้อนหลังต้องยังแสดงชื่อหรือ reference ได้

#### Frontend Behavior

- แสดง badge สถานะ inactive
- ซ่อนออกจาก selector ปกติ หรือแสดงแบบ disabled
- หน้าย้อนหลังยังดูรายละเอียดได้

### 3. `INACTIVE -> ACTIVE`

#### Trigger

- ผู้ใช้เปิดใช้งานสินค้าอีกครั้ง

#### Preconditions

- ข้อมูลหลักยัง valid
- unit / barcode / price configuration ยังใช้งานได้

### 4. `ACTIVE/INACTIVE -> ARCHIVED`

#### Trigger

- ธุรกิจต้องการเก็บ record ไว้ย้อนหลังโดยไม่ให้ใช้งานใน flow ปัจจุบัน

#### Effects

- ไม่ใช้ใน workflow ใหม่
- ยังคง referential meaning ใน order history, product history และ reports

## ข้อควรระวัง

- ไม่ควร hard delete สินค้าที่เคยถูกใช้ใน order, receive, หรือ report
- การเปลี่ยนสถานะสินค้าต้องไม่ทำให้เอกสารย้อนหลังเสีย integrity
- สินค้าที่ inactive แต่ยังมี stock ควรถูกจัดการตามนโยบายสต็อกให้ชัดเจน
