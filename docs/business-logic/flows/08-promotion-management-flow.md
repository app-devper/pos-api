# 08. Promotion Management Flow

## เป้าหมาย

ให้ผู้ใช้ธุรกิจสร้างและดูแลโปรโมชันได้อย่างถูกต้อง พร้อมลดความเสี่ยงจากการตั้งค่าเงื่อนไขผิดพลาด

## Actors

- ADMIN
- SUPER
- Frontend หน้า promotions
- Backend promotion services

## Preconditions

- ผู้ใช้มีสิทธิ์จัดการโปรโมชัน

## Main Flow

1. ผู้ใช้เปิดหน้าจัดการโปรโมชัน
2. Frontend โหลด promotions list และข้อมูลอ้างอิงที่จำเป็น
3. ผู้ใช้สร้างหรือแก้ไขโปรโมชัน
4. Frontend ตรวจ form เบื้องต้น เช่น code, dates, values
5. Backend ตรวจ validation เชิงธุรกิจและบันทึก
6. ผู้ใช้เปิด/ปิดสถานะโปรโมชันตามต้องการ
7. POS ใช้ข้อมูลโปรโมชัน active ในการคำนวณส่วนลด

## Error Flow

- code ซ้ำ → reject และแจ้งผู้ใช้
- วันที่ไม่ถูกต้อง → block ก่อน submit
- เปิดใช้งานไม่สำเร็จ → สถานะบนหน้าจอต้องไม่เพี้ยนจาก backend

## Expected Outcome

- โปรโมชันถูกตั้งค่าและใช้งานได้อย่างคาดเดาได้
- ลดปัญหาส่วนลดผิดหรือโปรโมชันหมดอายุแล้วยังถูกใช้
