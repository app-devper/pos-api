# 05. Customer Management Flow

## เป้าหมาย

จัดการข้อมูลลูกค้าและประวัติการซื้อให้พร้อมใช้งานทั้งในเชิงบริการหน้าร้านและการวิเคราะห์ความสัมพันธ์กับลูกค้า

## Actors

- พนักงานขาย
- เจ้าหน้าที่หน้าร้าน
- Frontend หน้า customers
- Backend customer services

## Preconditions

- ผู้ใช้มีสิทธิ์เข้าถึงหน้าลูกค้า
- branch context ถูกต้องถ้าข้อมูลลูกค้าถูกผูกตามสาขา

## Main Flow

1. ผู้ใช้เปิดหน้าลูกค้า
2. Frontend โหลด customer list และ search/filter state
3. ผู้ใช้ค้นหาหรือเลือกลูกค้าที่ต้องการ
4. ผู้ใช้สร้างหรือแก้ไขข้อมูลลูกค้า
5. Frontend validate ข้อมูลเบื้องต้นและส่งให้ Backend
6. Backend บันทึกข้อมูลและคืนข้อมูลล่าสุด
7. ผู้ใช้เปิดดู purchase history หรือเลือกลูกค้าไปใช้ใน POS

## Error Flow

- ข้อมูลไม่ครบ → block ก่อน submit หรือ reject จาก backend
- พบข้อมูลซ้ำ → แจ้งเตือนให้ตรวจสอบก่อนสร้างใหม่
- โหลดประวัติไม่สำเร็จ → list หลักยังควรใช้งานได้

## Expected Outcome

- ข้อมูลลูกค้าเป็นปัจจุบัน
- ใช้ในงานขายและประวัติย้อนหลังได้สะดวก
