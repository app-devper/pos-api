# 01. Dashboard Screen

## เป้าหมายของหน้าจอ

ให้ผู้ใช้เห็นภาพรวมของร้านในระดับสาขาอย่างรวดเร็ว เพื่อใช้ติดตามยอดขาย สถานะ stock และรายการที่ต้องรีบจัดการ

## ผู้ใช้เป้าหมาย

- SUPER
- ADMIN
- USER ที่ได้รับสิทธิ์เข้าถึง dashboard

## ข้อมูลที่ต้องโหลด

- ยอดขายวันนี้
- จำนวนสินค้าในระบบ
- รายการ stock ต่ำ
- รายการใกล้หมดอายุ
- กราฟยอดขายตามช่วงเวลา
- refill reminders หากเปิด feature ผู้ป่วย

## องค์ประกอบหลักของ UI

- summary cards
- charts
- alert sections
- quick links ไปยังหน้าที่เกี่ยวข้อง

## Action หลักของผู้ใช้

- เปลี่ยนช่วงเวลาของกราฟหรือข้อมูลสรุป
- กดดูรายการละเอียดของ stock ต่ำหรือใกล้หมดอายุ
- ใช้ dashboard เป็นจุดนำทางไปยัง feature อื่น

## Validation และ Feedback

- ถ้าข้อมูลบาง widget โหลดไม่สำเร็จ ต้องแยก error เฉพาะส่วนนั้นได้
- metric ต้องมี label ชัดเจนว่าคำนวณจากช่วงเวลาใด

## Empty / Loading / Error State

- loading state ต้องไม่ทำให้หน้าโยกแรงเกินไป
- ถ้าไม่มีข้อมูลในช่วงนั้น ให้แสดง empty state ที่อ่านเข้าใจง่าย
- ถ้าบาง service ล้มเหลว หน้าควรยังใช้งานส่วนอื่นได้

## ความสัมพันธ์กับ Backend

- Backend ให้ข้อมูล summary, analytics, inventory alerts และ refill data
- Frontend รับผิดชอบการนำเสนอข้อมูลให้เข้าใจง่ายและตอบสนองเร็ว
